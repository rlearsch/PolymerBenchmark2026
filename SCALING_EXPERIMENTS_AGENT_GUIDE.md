# Polymer Benchmark 2026 (PolyBench26): Dataset Scaling Experiment Guide

This file is intended for an LLM agent or automation process that needs to continue, audit, rerun, or extend the dataset-size scaling experiments in this repository.

For fresh-clone setup and new-model integration, first read
[`AGENTS.md`](AGENTS.md),
[`docs/REPRODUCING_RESULTS.md`](docs/REPRODUCING_RESULTS.md), and
[`docs/ADDING_A_MODEL.md`](docs/ADDING_A_MODEL.md).

## Goal

Measure how model performance changes as training-set size increases while holding validation and test chemicals fixed within each fold and keeping chemically identical splits across representations.

The key invariant is:

```text
same fold + different train size => same validation set and same test set
same fold + same train size + different representation => same chemicals
different fold => different validation/test chemicals
```

Training sets are nested within a fold:

```text
train_300 subset train_1000 subset train_3000 subset train_10000
```

## Split Generation

Canonical fold assignments are tracked under `Datasets/scaling_indices/`.
Custom models should consume those arrays directly; generating the full split
tree is necessary only for the built-in representation trainers.

Generate the complete published experiment matrix with:

```bash
bash Datasets/Dataset_construction_scripts/generate_scaling_datasets.sh
```

Use the lower-level command below to create or extend a single experiment.

Splits are generated by:

```bash
python Datasets/Dataset_construction_scripts/create_scaling_splits.py \
  --dataset MD_5000 \
  --property Cp \
  --file alternating_Cp.csv \
  --train-sizes 300 1000 3000 10000 \
  --num-folds 5 \
  --seed 42 \
  --overwrite
```

The split generator writes to:

```text
Datasets/scaling_splits/<dataset>/<property>/<file_stem>/seed_42/
```

Each experiment has:

```text
manifest.json
fold_00/
  indices/
  train_300/
    indices/
    PSMILES/
    wPSMILES/
    polyBERT/
    RDKit_descriptors/
  train_1000/
  ...
fold_01/
...
```

## Canonical Alignment

`PSMILES` is the canonical chemical ordering. The split generator validates that `wPSMILES` and `polyBERT` have matching row counts, target columns, and target values. RDKit descriptors are regenerated from the canonical PSMILES rows because existing RDKit descriptor files may not retain enough identity information to guarantee chemical alignment.

Do not create new random splits inside model trainers. Always train against these explicit split files.

## Model Training Scripts

### RDKit Random Forest

```bash
python Models/RDKit_RF/train_rf_scaling.py \
  --split-root Datasets/scaling_splits/MD_5000/Cp/alternating_Cp/seed_42 \
  --save-root Models/RDKit_RF/scaling_results/MD_5000/Cp/alternating_Cp/seed_42
```

Use the RDKit environment:

```bash
Models/RDKit_RF/.venv/bin/python Models/RDKit_RF/train_rf_scaling.py ...
```

### polyBERT

```bash
python Models/polyBERT/train_pBERT_scaling.py \
  --split-root Datasets/scaling_splits/MD_5000/Cp/alternating_Cp/seed_42 \
  --save-root Models/polyBERT/scaling_results/MD_5000/Cp/alternating_Cp/seed_42
```

Use the polyBERT environment:

```bash
Models/polyBERT/.venv/bin/python Models/polyBERT/train_pBERT_scaling.py ...
```

### polymer_chemprop And polymer_periodic_graph

Use:

```bash
bash scripts/train_graph_scaling.sh polymer_chemprop
bash scripts/train_graph_scaling.sh polymer_periodic_graph
```

These can be run in parallel in separate terminals. The script uses explicit split files and passes `--separate_val_path` and `--separate_test_path` to prevent internal random splitting.

Output locations:

```text
Models/polymer_chemprop/scaling_results/...
Models/polymer_periodic_graph/scaling_results/...
```

Each graph run writes logs to:

```text
.../train_<size>/fold_<nn>/train.log
```

## Result Collection

Collect all available model outputs into `scaling_results/` with:

```bash
bash scripts/collect_scaling_results.sh
```

Collect one experiment only:

```bash
bash scripts/collect_scaling_results.sh --only MD_5000/Cp/alternating_Cp
```

Per-experiment summaries are written to:

```text
scaling_results/<dataset>/<property>/<file_stem>/seed_42/scaling_results_detailed.csv
scaling_results/<dataset>/<property>/<file_stem>/seed_42/scaling_results_aggregate.csv
```

The combined summary is written to:

```text
scaling_results/all_seed_42/scaling_results_detailed.csv
scaling_results/all_seed_42/scaling_results_aggregate.csv
```

## Important Caveats

- For RDKit and polyBERT scaling trainers, train, validation, and test metrics are collected.
- For graph models, Chemprop-style outputs currently expose test RMSE in the central collector. Train/validation metrics are not summarized unless additional graph-model logging is added.
- `n_folds` in aggregate summaries is the number of completed folds found at collection time. For partially completed graph runs, this may be less than 5.
- Do not compare partially completed graph aggregates directly to completed 5-fold RDKit/polyBERT aggregates without noting `n_folds`.
- The split seed is `42`; graph model training currently uses `--seed 0 --pytorch_seed 0` for model initialization/training reproducibility while using the externally fixed split files.

## Quick Sanity Checks

After collecting results, inspect test rows:

```bash
python - <<'PY'
import pandas as pd
p = 'scaling_results/all_seed_42/scaling_results_aggregate.csv'
df = pd.read_csv(p)
print(df[df['split'] == 'test'][['experiment', 'model', 'train_size', 'rmse_mean', 'rmse_std', 'n_folds']])
PY
```

For a single experiment:

```bash
python - <<'PY'
import pandas as pd
p = 'scaling_results/MD_5000/Cp/alternating_Cp/seed_42/scaling_results_aggregate.csv'
df = pd.read_csv(p)
print(df[df['split'] == 'test'])
PY
```
